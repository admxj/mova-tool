# 火车票下单调试设计

首版范围（已确认）：选站查票、选择车次席别、填单、验价和业务校验、提交占座、查询订单状态。不接入支付、出票操作或退改，也不在工具内处理 12306 认证挑战；未绑定账号时提示先在 H5 完成绑定。

## 方案

复用调试工具的标签页、请求封装和检查器，新增火车票分步页。相比照搬 H5 页面，保留相同的业务校验链，但以便于定位请求和校验结果为主；相比仅提供 JSON 请求按钮，自动带入上一步载荷，降低混用报价或订单的风险。

## 接口与状态

- Java：车站 `/train/station/search`，查票 `/train/search`，车次信息 `/train/info`；保留站点和城市编码、车次内部编码和车次号，按席别组装报价。
- Java：获取企业乘车人 `/passenger/list` 和当前员工绑定账号 `/train/accounts/12306`。
- Java：`POST /train/orders/price`，必须获得有效 `quoteToken`。金额以分为单位。
- Go：按 H5 的 TRAIN/BOOK 语义处理申请单豁免与校验，随后调用 `/v1/co/check/travel/policy/check`；阻断结果不允许创单，确认类差标按 H5 要求二次校验，仅传递实际生效的超标审批 ID。
- Java：在明确确认后 `POST /train/orders` 占座，显式区分上线环境，复用同一提交尝试的幂等键；以 `GET /train/orders/{orderNo}` 查询订单，并区分订单、履约和支付状态。
- 修改影响报价或提交的字段，或切换环境、登录、租户时，作废旧流程状态；丢弃跨上下文返回的请求结果。

## 验证

以模拟请求测试字段传递、验价和申请单/差标阻断、幂等重试、订单状态及环境切换。不向实际环境发送占座或付款请求。
